Setup & Installation

6 questions
Q What are the system requirements? ▾

The copilot requires Python 3.11 or higher. It has been tested on Python 3.11, 3.12, and 3.14.

Python 3.11+Windows / Mac / Linux
Q How do I install dependencies? ▾
  1. Navigate into the project folder: cd AI-CapstoneProjects
  2. Install from the requirements file: pip install -r requirements.txt

The three core dependencies are anthropic, python-dotenv, and requests. No LangChain or heavy ML frameworks required.

Q How do I set up my API key? ▾
  1. Copy the template: copy .env.example .env (Windows) or cp .env.example .env (Mac/Linux)
  2. Open .env in any text editor
  3. Replace the placeholder with your real key from console.anthropic.com
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxxxxxxxxxx
⚠
Do not add quotes or spaces around the key. ANTHROPIC_API_KEY="sk-ant-..." will fail.
Q Where do I get an Anthropic API key? ▾
  1. Visit console.anthropic.com and sign in
  2. Click API Keys in the left sidebar
  3. Click Create Key and copy the full key
  4. Paste it into your .env file

The key starts with sk-ant- and is approximately 100 characters long.

Q What is the correct folder structure? ▾ 
AI-CapstoneProjects\
├── main.py              ← entry point (run THIS)
├── .env                 ← your API key
├── requirements.txt
├── conftest.py
├── pyproject.toml
└── copilot\
    ├── __init__.py
    ├── __main__.py
    ├── config.py
    ├── memory.py
    ├── orchestrator.py
    ├── agents.py
    └── tools.py
⚠
main.py must be in the root folder, NOT inside the copilot\ subfolder.
Q Can I install it as a package instead? ▾

Yes. Installing in editable mode makes imports work from any directory:

cd AI-CapstoneProjects
pip install -e .

After this you can also run the copilot via pm-copilot or python -m copilot from anywhere on your system.

Running the App

5 questions
Q How do I start the copilot? ▾ 
cd AI-CapstoneProjects
python main.py

You will see the startup banner and a You › prompt where you type your requests in plain English.

Q Are there command-line parameters? ▾

No. The app runs as an interactive REPL. All input is typed at the You › prompt after launch. The only environment-level option is passing the API key inline:

# Windows PowerShell
$env:ANTHROPIC_API_KEY="sk-ant-xxx"; python main.py

# Mac / Linux
ANTHROPIC_API_KEY=sk-ant-xxx python main.py
Q What commands can I type at the prompt? ▾

Three built-in commands are available at the You › prompt:

memory    → print the current long-term memory store
exit      → quit the application
Ctrl+C    → also quits

Everything else is treated as a natural language request and sent to the orchestrator.

memoryexitCtrl+C
Q What are some example questions I can ask? ▾ 
You › Plan the next sprint
You › What are the risks this sprint?
You › Write user stories for the authentication feature
You › Review the latest pull request
You › Generate today's standup digest
You › When is the next sprint meeting?
You › What did we decide about the database last week?
Q How do I run the tests? ▾ 
cd AI-CapstoneProjects
python -m pytest tests/ -v

All 19 tests should pass. Tests use mocked Anthropic API calls so no API key is needed to run them.

✦
Run pip install pytest first if pytest is not installed.

Agents & Routing

5 questions
Q What specialist agents are available? ▾

Five specialist agents are built in:

requirements    → PRDs, user stories, acceptance criteria
sprint_planner  → backlog ranking, velocity, sprint plans
risk_analyst    → blockers, dependencies, deadline risk
code_reviewer   → PR analysis, bug flags, quality gate
standup         → daily digest, nudges, status summary
Q How does the orchestrator decide which agent to call? ▾

The orchestrator sends your message to the reasoning model with a routing prompt. The model returns a JSON object specifying which agents to invoke:

{"intent": "plan sprint", "agents": ["sprint_planner"], "context_needed": ["tickets"]}

If no agent matches (e.g. casual chat), the orchestrator answers directly without invoking any specialist.

Q Can multiple agents run at the same time? ▾

Yes. The orchestrator can dispatch multiple agents for a single request. For example, "what are the risks and how should I adjust the sprint?" will invoke both risk_analyst and sprint_planner. Their outputs are merged by the orchestrator into a single coherent response.

✦
Current implementation dispatches agents sequentially. Parallel execution is a planned extension.
Q Which LLM model does each agent use? ▾ 
code_reviewer   → CODE_MODEL   (set in .env, default: claude-sonnet-4-20250514)
all other agents → REASONING_MODEL (set in .env, default: claude-sonnet-4-20250514)

You can override either model in your .env file:

REASONING_MODEL=claude-opus-4-20250514
CODE_MODEL=claude-sonnet-4-20250514
Q What is the review gate? ▾

After agents return results, the orchestrator runs a quality check. If the combined response is incomplete or ambiguous, it triggers one automatic retry with a refined sub-query. If the second attempt still falls short, the best available answer is returned anyway.

{"status": "approved"}               → response returned to user
{"status": "retry", "refined_query": "..."} → one retry triggered

Memory System

5 questions
Q What is the difference between short-term and long-term memory? ▾

Short-term memory (STM) is the active context window for the current session — conversation turns, tool outputs, and retrieved memories. It is wiped when the session ends.

Long-term memory (LTM) is persisted to disk as data/ltm.json. It survives across sessions and is retrieved at the start of each new session via semantic search.

Q What gets stored in long-term memory? ▾

LTM is organised into five categories:

project     → goals, milestones, PRDs, architecture decisions
team        → member roles, velocity history, preferences
decisions   → choices made, rationale, rejected alternatives
compressed  → session summaries, evicted STM turns
signals     → defect patterns, PR cycle times, risk entries
Q How does vector search / RAG work? ▾

Every item written to LTM is converted to a TF-IDF vector and stored. When a new session starts or an agent needs context, your query is also vectorised and compared against all stored vectors using cosine similarity. The top-k most relevant entries (default: 5) are injected into the active context window.

✦
The vector store is pure Python — no external vector database required. It runs entirely in memory.
Q What happens when the context window gets too full? ▾

When the number of conversation turns exceeds stm_max_turns (default: 20), the oldest half of turns are summarised and written to the compressed LTM category. The raw turns are then evicted from the active window. This keeps the context lean without losing important history.

# Override in .env
STM_MAX_TURNS=30
Q How do I inspect or reset long-term memory? ▾

Type memory at the prompt to print a summary of all LTM categories.

To reset LTM completely, delete the file:

# Windows
del data\ltm.json

# Mac / Linux
rm data/ltm.json

The file will be recreated fresh on the next run.

Integrations

4 questions
Q Do I need Jira, GitHub, or Slack to use the copilot? ▾

No. All integrations are optional. When credentials are absent, every tool call falls back to realistic demo data automatically. You can explore the full copilot experience with only an Anthropic API key.

✦
Demo mode uses pre-built ticket lists, PR diffs, and team data that match realistic project scenarios.
Q How do I connect Jira? ▾

Add these three values to your .env file:

JIRA_URL=https://your-org.atlassian.net
JIRA_USER=you@yourorg.com
JIRA_TOKEN=your_jira_api_token

Get your Jira API token at id.atlassian.com/manage-profile/security/api-tokens.

Q How do I connect GitHub? ▾ 
GITHUB_TOKEN=ghp_your_personal_access_token
GITHUB_REPO=your-org/your-repo

Create a personal access token at github.com/settings/tokens. The token needs repo scope to read PR diffs.

Q How do I connect Slack? ▾ 
SLACK_TOKEN=xoxb-your-bot-token
SLACK_CHANNEL=#dev-updates

Create a Slack bot at api.slack.com/apps, add the chat:write OAuth scope, install it to your workspace, and copy the Bot User OAuth Token.

Errors & Fixes

7 questions
Q ModuleNotFoundError: No module named 'copilot' ▾

You are running from the wrong directory. You must be inside the project root where main.py lives:

cd AI-CapstoneProjects
python main.py

Or install the package so it works from anywhere:

pip install -e .
Q ModuleNotFoundError: No module named 'copilot.orchestrator' ▾

main.py is probably inside the copilot\ folder instead of next to it. Move it out:

move copilot\main.py main.py

Then verify the structure matches the layout shown in the Setup section.

Q NameError: name 'Config' is not defined ▾

A stale __pycache__ or partial import is preventing copilot/__init__.py from loading. Clear the cache and retry:

# Windows
rmdir /s /q copilot\__pycache__
python main.py

# Mac / Linux
rm -rf copilot/__pycache__
python main.py
Q anthropic.AuthenticationError: invalid x-api-key (401) ▾

Your API key is missing, wrong, or malformed. Open .env and check:

ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxx   ← no quotes, no spaces
✕
Common mistakes: key wrapped in quotes, leading/trailing space, key copied incompletely, or .env file not saved.

Get a fresh key at console.anthropic.com → API Keys.

Q cannot import name 'create_tool_calling_agent' from 'langchain.agents' ▾

This project does not use LangChain at all. If you see this error you are running a different file — not the one from this project.

  1. Confirm you are in the right folder: cd AI-CapstoneProjects
  2. Check the first lines of your file: type main.py — it should say AI PM Copilot — Main entry point
  3. If not, re-download the files from the source and replace them
Q SyntaxError: from __future__ imports must occur at the beginning of the file ▾

A previous patch injected path-bootstrap code before a from __future__ import annotations line. Clear Python's cache to force a clean re-read:

rmdir /s /q copilot\__pycache__   (Windows)
rm -rf copilot/__pycache__        (Mac/Linux)

Then re-download the latest copilot/memory.py and copilot/agents.py from the shared files above, which have the correct ordering.

Q python -m pytest tests/ fails with import errors ▾

Make sure you run pytest from inside the project root and that conftest.py is present there:

cd AI-CapstoneProjects
dir conftest.py      ← must exist
python -m pytest tests/ -v

If conftest.py is missing, create it with:

import os, sys
ROOT = os.path.dirname(os.path.abspath(__file__))
if ROOT not in sys.path:
    sys.path.insert(0, ROOT)
